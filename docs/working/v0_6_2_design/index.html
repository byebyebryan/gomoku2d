Refinement from Bryan's feedback

Keep the left about the player. Put the record with the games.

The two columns now follow the existing Profile screen. The left panel holds the public name and Copy link. The right panel starts with A's compact shared record, followed by the published game list. Hidden statistics collapse away; the left panel stays short instead of stretching to match the games.

On mobile, identity becomes a compact row above the record and games. This keeps useful content near the top while preserving all five existing statistics when shared. No avatar, bio, extra metric or placeholder content is needed.

Research and constraints

  • The strongest visual references are our own Profile, Settings, Replay and Rules surfaces. The study copies the current global stylesheet, actual PixelOperator fonts and existing 24px SVG icons into its export.
  • Chess.com Game Collections keeps game curation near Analysis and makes visibility explicit. This supports clear reader/owner roles; it does not justify folders or a community catalog here.
  • W3C consistent navigation informs stable control placement. W3C reflow guidance informs narrow/enlarged-text checks. Prototype checks are not human accessibility or device acceptance.
  • A live Lichess profile returned HTTP 403 during research, so it is not treated as an inspected visual reference. No competitor profile screenshot is implied.
  • No new public fields, schema changes, avatars, bios, ratings, game dates, featured games, background listeners or services. Existing snapshot date and all five current statistics remain visible when shared.
